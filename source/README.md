# Норма · GraphRAG Workbench для диссертации

Веб-приложение для исследования структурированной семантической модели из
[f0k3s/dissertation](https://github.com/f0k3s/dissertation).

## Что работает

- Трёхмерный граф, вращение, приближение, плоская проекция, выбор и окружение узла.
- Автоматический совместимый 3D-рендерер Canvas, если WebGL 2 недоступен.
- Раздельные слои: модель ГОСТ, переиспользуемая онтология, архив.
- Поиск русских названий и идентификаторов, фильтрация типов.
- Требования, числовые и перечислимые значения, условия, методы контроля и ссылки на фрагменты.
- Поиск фактов по ключевым словам и структуре графа, без вызовов языковой модели.
- Кратчайшие пути с указанием реального направления каждого отношения.
- Просмотр исходных JSON-LD, SHA-256, ссылки на точную версию GitHub.
- Экспорт и импорт `.graphrag.json`, JSON-LD и папок с локальными контекстами.
- Сохранение импортированного проекта в IndexedDB. Кнопка восстановления исходного снимка.
- CSV требований и JSON отдельного узла.

## Важные границы

Это адаптация интерфейса и формата **GraphRAG Workbench**, рассчитанная на уже
структурированные данные. В браузере не запускается Python-индексатор Microsoft
GraphRAG; нет извлечения сущностей из PDF, embeddings, LanceDB, LLM-ответов и
автоматических отчётов сообществ. Для имеющейся JSON-LD-модели импортируются
существующие отношения, вместо их повторного извлечения моделью. API-ключ не нужен.

Группировка выполняется по типу сущности; она не представляется как результат
кластеризации Microsoft GraphRAG. Поиск фактов — детерминированное сопоставление
ключевых слов с требованиями и связанными узлами; он не понимает произвольный
естественный язык и не выполняет нормативную экспертизу.

Исходный набор сам описан как исследовательская модель по мотивам анализа
ГОСТ 13579-2018, а не полная цифровая копия стандарта. Числовые данные не заменены
значениями из внешних источников. Даты, статусы и фрагменты показываются как
записано в репозитории, без проверки актуальности стандарта.

## Данные и происхождение

Снимок репозитория: `f3d1fa8a76e80792a23d9c9d234edb6f295eb683`.

Импортирован 21 JSON-LD: 13 файлов актуальной модели и 8 архивных JSON-LD.
Результат адаптации: **298 узлов и 560 связей**, включая вложенные значения и
внешние ссылки. В документном слое — **15 требований**. XML и изображение схемы
не интерпретируются как утверждения и не включены в граф.

`src/core/ingest.mjs` — структурный адаптер прикладного диалекта JSON-LD этого
репозитория, а не полноценный RDF/OWL-процессор:

- локальные контексты разрешаются относительно файла; удалённые не скачиваются;
- `id`/`type` и `@id`/`@type` поддерживаются;
- компактные идентификаторы расширяются по префиксам, когда это однозначно;
- одинаковые метки не являются основанием для объединения узлов;
- документная модель и онтология остаются отдельными слоями и пространствами имён;
- повторные описания одного идентификатора объединяют значения и отношения;
- вложенные количественные значения получают устойчивые идентификаторы и связи с единицами;
- `hasValue: enum:*` трактуется как ссылка лишь при наличии соответствующего узла;
- отсутствующие определения сохраняются внешними ссылками с диагностикой;
- неоднозначное объявление `unit` в исходном контексте явно отмечено;
- оригинальные тексты файлов и их контрольные суммы сохраняются в снимке и пакете экспорта.

Импорт ограничен 20 МБ, 300 файлами и 4 000 узлами. Большие GraphRAG-проекты
следует исследовать оригинальным локальным Workbench. Новый импорт проверяется
перед заменой проекта; повреждённый пакет не уничтожает открытый граф.

## Локальный запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm ci
npm run dev
```

Откройте `http://localhost:4173/`. Сервер разработки предназначен для локальной
работы. Рабочие данные уже включены; клонировать исходный репозиторий для запуска
не требуется.

Проверка и сборка:

```bash
npm test
npm run build
```

`dist/` можно разместить на статическом HTTPS-хостинге в корне домена. Страница
использует абсолютные пути `/data/` и `/assets/`. Открытие `index.html` через
`file://` не поддерживается. Рабочий сайт публикуется приватным через Sites.

## Обновить снимок

```bash
git clone https://github.com/f0k3s/dissertation.git /path/to/dissertation
npm run data -- /path/to/dissertation
npm test
npm run build
```

Скрипт сохраняет точный Git commit, оригинальные файлы и SHA-256, пересоздаёт
граф и совместимые артефакты. Автоматической синхронизации с GitHub нет.

## Открыть граф в оригинальном Workbench

1. В приложении нажмите «Экспорт графа».
2. Запустите [оригинальный GraphRAG Workbench](https://github.com/lyon-industries/graphrag-workbench)
   согласно его README.
3. В Projects создайте именованный проект и выберите **Import bundle**.
4. Укажите скачанный `dissertation.graphrag.json`.

Альтернатива: импортировать папку `public/data/workbench/` через Import directory.
Пакет содержит `entities`, `relationships`, `communities`, `community_reports`
(пустой массив, отчёты не генерируются) и `text_units`. Дополнительное поле `norma`
позволяет восстановить исходные идентификаторы, слои, диагностику и файлы в этом
приложении; оригинальный Workbench игнорирует это расширение.

## Проверки

Автотесты проверяют сохранность 15 требований, вложенных значений и единиц,
полноту связей с источниками, разные пространства имён, повторные описания,
оба способа записи типов, поиск путей, roundtrip пакета, отказ на повреждённых
ссылках и SHA-256 всех 21 исходного файла.

В браузере проверены навигация, поиск ФБС, факты о размерах и прочности,
фильтр нормативной силы, путь ФБС → требование 003 → длина, скачивание пакета,
обратный импорт, сохранение после перезагрузки и восстановление исходного снимка.
Среда проверки не предоставляет WebGL; проверен совместимый рендерер Canvas.
Нативная WebGL-ветка проходит проверку TypeScript и сборку.
